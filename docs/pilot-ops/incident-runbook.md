# รับมือเหตุขัดข้องและเหตุฉุกเฉิน

## เริ่มจัดการเหตุ

1. **เหตุคุกคามความปลอดภัย** ให้ผู้เกี่ยวข้องถอยไปยังจุดปลอดภัยและติดต่อหน่วยฉุกเฉินในพื้นที่ทันทีเมื่อมีอันตรายหรือผู้บาดเจ็บ แจ้งหัวหน้าเวรเมื่อปลอดภัย ให้เวรดูแลออเดอร์ค้างและประสานผู้เกี่ยวข้อง
2. เปิดเลขเหตุการณ์ บันทึกเวลาเริ่ม (ICT) พื้นที่ บริการ รุ่นแอป อาการ จำนวนงานที่ทราบ สถานะงานเดิม และผู้รับผิดชอบ แยกเหตุเฉพาะรายออกจากเหตุที่ยังขยายวง กรณีความปลอดภัย ข้อมูลส่วนบุคคล หรือเงินผิดหลายรายการ ให้แจ้งหัวหน้าเหตุการณ์ทันที
3. หัวหน้าเหตุการณ์ยืนยันขอบเขตและผู้มีสิทธิ์สั่งพักรับงาน หากระบบควบคุมใช้งานได้ ให้ผู้มีสิทธิ์ใช้ช่องทางปฏิบัติการที่ซ้อมไว้และตรวจสถานะยืนยัน หากใช้ไม่ได้ ให้หยุดเชิญให้สั่งหรือเปิดรับงานผ่านช่องทางประสานที่อนุมัติ และติดตามออเดอร์เดิมทีละรายการ
4. มอบหมายผู้สื่อสารหนึ่งคน แจ้งเฉพาะพื้นที่ บริการที่ได้รับผลกระทบ สิ่งที่ผู้ใช้ควรทำ และเวลานัดอัปเดตตามเวรจริง ใช้ช่องทางจำกัดสิทธิ์สำหรับออเดอร์และหลักฐาน หลีกเลี่ยงการส่งพิกัดละเอียด รูปเต็ม โทเคน หรือข้อมูลการเงินในห้องสาธารณะ

| เหตุ | จำกัดผลกระทบและส่งต่อ |
| --- | --- |
| สั่งซื้อหรือ Checkout ไม่สำเร็จ | ตรวจว่าระบบสร้างออเดอร์หรือบิลเดิมแล้วหรือยัง ตรวจผลรับเงินผ่านผู้มีสิทธิ์ งดสร้างหรือเก็บเงินซ้ำเมื่อผลคลุมเครือ ส่งเลขเคสและอาการให้ทีมของช่องทางที่เสีย |
| ระบบล่มหรือสถานะหลายฝ่ายไม่ตรง | เปิดรายการออเดอร์ค้างตามสถานะที่ยืนยันได้ ระบุผู้ดูแลแต่ละรายการ พักบริการที่ได้รับผลตามอำนาจเวร ส่งเวลา ขอบเขต และรุ่นให้ Worker 2/3 หรือ Worker 1 ตามอาการ ประสาน Worker 4 เรื่องรุ่นและหลักฐานกู้คืน |
| GPS ผิด แผนที่ว่าง หรือนำทางออฟไลน์ไม่ได้ | ให้ไรเดอร์จอดในจุดปลอดภัย ตรวจสิทธิ์และสัญญาณ ประสานจุดส่งผ่านช่องทางที่อนุมัติ งดมอบหมายงานที่ต้องพึ่งเส้นทางที่ยังตรวจไม่ได้ ส่งรุ่น อาการ และเวลาให้ Worker 1 |
| ยอดผิด ตัดซ้ำ หรือคืนเงินไม่ชัด | หยุดขอให้ชำระซ้ำ ให้ผู้มีสิทธิ์กระทบยอดหลักฐานช่องทางรับเงินกับออเดอร์หรือบิลเดิม ส่งต่อผู้รับผิดชอบการเงินและ Worker 2 เมื่อเกี่ยวกับข้อมูลระบบ |
| สงสัยข้อมูลส่วนบุคคลรั่ว | จำกัดการเข้าถึงหลักฐาน เก็บเวลา แหล่งที่พบ และขอบเขตเท่าที่ทราบ แจ้งเจ้าของเหตุด้านข้อมูลผ่านช่องทางภายในและให้ผู้มีสิทธิ์จัดการการเข้าถึง |

## ฟื้นบริการและส่งมอบ

หัวหน้าเหตุการณ์ตรวจรายการค้างและยอดที่ไม่ชัดให้มีผู้รับช่วงครบ ให้ Worker ที่รับงานยืนยันหลักฐานกู้คืนของรุ่นที่ใช้ และให้เจ้าของโครงการหรือผู้ได้รับมอบหมายตัดสินเปิดรับอีกครั้งตาม [รายการ Go/No-Go](pilot-go-no-go.md) บันทึกเวลาฟื้นบริการ ผู้อนุมัติ เคสที่ยังติดตาม และวันทบทวนเหตุ การย้อนรุ่นหรือกู้ฐานข้อมูลเป็นหน้าที่ของผู้มีสิทธิ์ตามแผนที่อนุมัติ

แบบบันทึกเหตุใช้ช่อง **เลขเหตุ / เวลาและพื้นที่ / ผลกระทบ / งานค้าง / การตัดสินใจและผู้อนุมัติ / เจ้าของแต่ละงาน / เวลานัดอัปเดต / หลักฐานจำกัดสิทธิ์ / ผลกู้คืน** เก็บในทะเบียนเหตุของกะ
