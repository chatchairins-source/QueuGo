# ดูแลลูกค้าและจัดการปัญหาออเดอร์

## รับเรื่องและติดตาม

1. ให้ลูกค้าเปิดเรื่องจากบัญชีเจ้าของออเดอร์ผ่านช่องทางที่อนุมัติ หากเข้าระบบไม่ได้ให้ใช้ช่องทางเวรที่ผู้ประสานพื้นที่กำหนด ตรวจสิทธิ์ผู้แจ้งก่อนเปิดเผยรายละเอียดออเดอร์
2. บันทึกเลขเคส เลขออเดอร์ เวลาที่เกิดเหตุ (ICT) ประเภทปัญหา สถานะล่าสุดในระบบ ผู้รับผิดชอบ และเวลานัดอัปเดต ใช้เลขเคสเดิมสำหรับรายงานซ้ำ หากแอปไม่มีเลขยืนยันให้ตรวจเรื่องเดิมก่อนสร้างเพิ่ม
3. เปิดรายการเดิมจากระบบตามสิทธิ์ ประสานร้านหรือไรเดอร์ผ่านช่องทางที่อนุมัติตามขั้นตอนล่าสุด แจ้งลูกค้าว่าตรวจอะไรแล้ว ใครรับช่วง และจะอัปเดตอีกเมื่อใดตามเวรจริง
4. ปิดเคสเมื่อบันทึกผลและหลักฐานที่ยืนยันได้ แจ้งผู้แจ้งและระบุงานติดตามที่ยังค้าง ถ้ามีรายการการเงินค้างให้คงผู้รับผิดชอบไว้จนยืนยันผล

| เคส | สิ่งที่ตรวจและดำเนินการ |
| --- | --- |
| ช้าหรือยังไม่มีไรเดอร์ | ตรวจร้านรับแล้วหรือไม่ พร้อมรับหรือยัง และมีไรเดอร์ผูกกับงานหรือไม่ ประสานฝ่ายที่ถือขั้นตอนล่าสุด ใช้เวลาประมาณที่ยืนยันได้ |
| หาออเดอร์ไม่พบ | ตรวจเลขออเดอร์ บัญชี และผลของรายการเดิม หากมีการตัดเงินให้ส่งต่อผู้ตรวจยอดก่อนแนะนำให้สั่งหรือจ่ายใหม่ |
| ส่งสำเร็จแต่ไม่ได้รับ หรือได้ไม่ครบ/ไม่ตรง | ตรวจสถานะและหลักฐานส่งมอบตามสิทธิ์ ขอเฉพาะข้อมูลรายการที่ได้รับผลกระทบ เทียบกับร้านและไรเดอร์ ส่งต่อเวรตัดสินเคส |
| ขอให้ยกเลิก | ตรวจสถานะและเงื่อนไขของบริการ ให้เจ้าของออเดอร์ใช้ปุ่มยกเลิกถ้าระบบมีให้และเข้าเงื่อนไข หากติดเงื่อนไขหรือผลไม่ชัด ให้ส่งต่อผู้มีสิทธิ์และตรวจสถานะเดิม |
| คืนเงิน ยอดผิด หรือตัดซ้ำ | ส่งเลขออเดอร์หรือเลขบิล ยอด เวลา และหลักฐานที่ปกปิดข้อมูลส่วนตัวให้ผู้มีสิทธิ์ตรวจสอบยอดและสถานะจริง แจ้งว่ารอตรวจสอบ ระบุยอดหรือวันคืนได้หลังมีผลยืนยันแล้ว |
| อุบัติเหตุ ภัยคุกคาม ข้อมูลรั่ว หรือกระทบหลายออเดอร์ | เปิด [Incident Runbook](incident-runbook.md) และยกระดับให้หัวหน้าเหตุการณ์ทันที |

ตัวอย่างข้อความ “รับเรื่องออเดอร์เลข … แล้วครับ ขณะนี้กำลังตรวจสอบสถานะกับ … เราจะอัปเดตอีกครั้งเวลา … ผ่านช่องทางนี้”

ใช้เฉพาะช่องทางจำกัดสิทธิ์ในการส่งหลักฐาน ปกปิดชื่อ เบอร์ ที่อยู่ และข้อมูลการเงินส่วนที่ไม่เกี่ยวข้องก่อนส่งต่อ งดขอ OTP รหัสผ่าน PIN หรือเลขบัตรเต็ม ใช้เลขออเดอร์และเลขเคสในสรุปทีม หากลูกค้าแจ้งผลชำระ ให้ผู้มีสิทธิ์ตรวจธุรกรรมในระบบเดิมโดยใช้ข้อมูลเท่าที่จำเป็น
